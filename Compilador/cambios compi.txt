Paso 4:

Las comptime son variables cuyos valores deben ser conocidos y determinables estrictamente en tiempo de compilación. Esto permite realizar optimizaciones.
Esto permite realizar optimizaciones (como el constant folding) y aplicar restricciones estrictas (por ejemplo, prohibir que se les asignen valores dinámicos o variables comunes que solo se conocen en tiempo de ejecución)

Cambios realizados:


En código intermedio.py:

Gestor de ámbitos:

-Se agrego un diccionario interno llamado self.valores_comptime = {}.
 Para mapear cada variable COMPTIME (por su nombre interno/mangleado) con su valor constante actual en tiempo de compilación

-Implementamos métodos para registrar (registrar_valor_comptime) y consultar(obtener_valor_comptime) dicho valor

Generador de código:

-Se modifico "variable". Se usa para cuando la variable aparece en el lado derecho de una expresión. Si es comptime, el compilador exige que ya tenga un valor constante registrado. Si no lo tiene, lanza un error semántico ("se usa antes de ser asingada"). Si no lo tiene, devuelve directamente su valor constante para que la expresión lo aproveche.

-Se agrego "variable_destino". Se crea para el lado izq de las asignaciones. No exige valor previo, ya que el propósito de ese momento es justamente asignarle un valor por primera vez

-Se modifico asignación. Cuando el destino es una variable COMPTIME, el generado valida que la expreison de la derecha sea verdaderamente un valor determinable en compilación (literal con sufijo $) como 3$ui o una constante plegada.
Si intentas asingarle una variable común, se intercepta y rechaza con un error semántico

-Se agrego operación. Si en una operación aritmética ambos operandos son constante estáticas con $, el compi calcula el resultado en tiempo de compilación(3+1 se vuelve 4$ui) en lugar de generar un terceto de ejecución en runtime


En analizadorsintactico.py:

Se ajustaron algunas reglas sintácticas:

-Separación del lado izquierdo. Las asignaciones (ref_variable TWO_POINTS_ASSING expresión) se desacoplaron de las lecturas normales.
El lado izquierdo de una asignación ahora pasa por variable_destino, evitando que el compilador rompa con un error de "variable no inicializada" justo cuando se le está dando valor por primera vez.
Las lecturas en expresiones y pout siguen usando el método tradicional variable.



Tabla de símbolos.py:


La estructura base de la tabla de símbolos ya almacenaba diccionarios con atributos para cada variable (permitiendo guardar banderas como comptime=True desde las reglas de declaración del parser).

Separación de responsabilidades: La Tabla de Símbolos se encarga de qué es cada variable (su tipo, su ámbito, si es comptime o común). Lo único que necesitábamos agregar era el estado dinámico de sus valores (el valor constante calculado en compilación), y de eso se encargó el GestorAmbitos con su diccionario interno valores_comptime, utilizando las búsquedas de la tabla (tabla.buscar(...)) tal cual como ya venían funcionando.

Así que el módulo de la Tabla de Símbolos quedó totalmente libre de cambios.

comptime integer x;
x := 3$ui;

Declaración: El analizador declara x en la tabla de símbolos marcando su atributo comptime = True.

Primera Asignación (x := 3$ui):

El parser detecta el x como destino_asignacion (llama a variable_destino sin exigir valor previo).

El generador valida que 3$ui es una constante válida y llama a ambitos.registrar_valor_comptime('x', 3$ui). Ahora x tiene el valor estático 3.

Segunda Asignación con Operación (x := x + 1$ui):

Al leer el primer x en la expresión, el generador llama a variable(). Como x es COMPTIME, el sistema busca en valores_comptime y recupera el valor 3$ui.

El método operacion detecta que ambos (3$ui y 1$ui) son constantes, aplica constant folding y genera un único operando constante resultante: 4$ui.

Se asigna el nuevo valor estático 4 a x.

AnalizadorSemantico: 
Durante el análisis sintáctico y la generación de código intermedio, se integraron las acciones semánticas que invocan al GestorAmbitos en puntos clave de la gramática:

Al declarar una clase: Se invoca amb.iniciar_clase(...) al abrir el bloque y amb.cerrar_clase(...) al cerrarlo.

Al declarar una sentencia friend: La acción semántica correspondiente invoca amb.registrar_amigo(...) para registrar el vínculo de amistad en tiempo de compilación.

Al declarar atributos o métodos dentro de una clase: La regla gramatical de miembros desvía la creación hacia amb.declarar_miembro(...), asegurando que se guarden con el prefijo de clase y su respectivo modificador de acceso.

Al utilizar o invocar un miembro (en expresiones o llamadas): Cada vez que el analizador detecta un acceso a un miembro (por ejemplo, accediendo a un atributo o ejecutando un método), invoca de manera obligatoria a amb.validar_y_obtener_miembro(...). Esto garantiza que el compilador frene cualquier intento de violación de encapsulamiento emitiendo el mensaje de error adecuado en la línea exacta.

def validar_y_obtener_miembro(self, clase_propietaria, nombre_miembro, linea):
    clase_actual_busqueda = clase_propietaria
    coincidencias = []

    while clase_actual_busqueda:
        nombre_interno = f"{clase_actual_busqueda}.{nombre_miembro}"
        info = self.tabla.buscar(nombre_interno)
        if info:
            coincidencias.append((clase_actual_busqueda, info))
        
        info_clase = self.tabla.buscar(clase_actual_busqueda, token='CLASS')
        clase_actual_busqueda = info_clase.get('padre') if info_clase else None

    # 2. Chequeo de ambigüedad (Opción 3)
    if len(coincidencias) > 1:
        clases_implicadas = ", ".join([c[0] for c in coincidencias])
        self.errores.semantico(
            linea, 
            f"Error semántico: El miembro '{nombre_miembro}' es ambiguo; "
            f"está declarado en múltiples clases de la jerarquía: [{clases_implicadas}]."
        )
        return None
    
    return coincidencias[0][1] if coincidencias else None


Acceso a Atributos y Métodos mediante el Operador Punto (.)

Cómo se implementa

Cada vez que el compilador procesa expresiones que involucran navegación de objetos o llamadas a miembros mediante punto (ej. objeto.atributo), la acción semántica asociada invoca de manera obligatoria al método centralizado validar_y_obtener_miembro del GestorAmbitos.

Este método centraliza las validaciones de existencia, herencia multinivel, visibilidad estricta (private/public) y control de amistad en un único punto de control.

Fragmentos de Código Clave

Flujo de Validación Centralizado (GestorAmbitos):


 def validar_y_obtener_miembro(self, clase_propietaria, nombre_miembro, linea):
            clase_actual_busqueda = clase_propietaria
            coincidencias = []

            # Búsqueda recursiva a través de toda la jerarquía recolectando TODAS las apariciones
            while clase_actual_busqueda:
                nombre_interno = f"{clase_actual_busqueda}.{nombre_miembro}"
                info = self.tabla.buscar(nombre_interno)
                if info:
                    coincidencias.append((clase_actual_busqueda, info))
                
                # Consultamos la clase padre para seguir ascendiendo en la jerarquía
                info_clase = self.tabla.buscar(clase_actual_busqueda, token='CLASS')
                clase_actual_busqueda = info_clase.get('padre') if info_clase else None

            # 1. Chequeo de existencia: Si no existe en ninguna clase de la jerarquía
            if not coincidencias:
                self.errores.semantico(linea, f"El miembro '{nombre_miembro}' no existe en la clase '{clase_propietaria}' ni en sus clases base.")
                return None
                
            # 2. Chequeo de ambigüedad (Opción 3): Si el miembro existe en más de una clase de la cadena
            if len(coincidencias) > 1:
                clases_implicadas = ", ".join([c[0] for c in coincidencias])
                self.errores.semantico(linea, f"Error semántico: El miembro '{nombre_miembro}' es ambiguo; está declarado en múltiples clases de la jerarquía: [{clases_implicadas}].")
                return None

            # Si hay exactamente una única coincidencia, extraemos su propietario real y metadatos
            propietario_real, info = coincidencias[0]

            # 3. Si el miembro encontrado es público, se permite directamente
            if info.get('visibilidad', 'public') != 'private':
                return info
                
            # 4. Si el miembro es PRIVADO, aplicamos las reglas de acceso:
            # ¿Estamos dentro de la misma clase EXACTA donde fue declarado el miembro privado?
            es_propio = (self.clase_actual == propietario_real)
            
            # ¿El ámbito actual es amigo de la clase propietaria real del miembro?
            info_clase_prop = self.tabla.buscar(propietario_real, token='CLASS')
            amigos_de_la_clase = info_clase_prop.get('amigos', set()) if info_clase_prop else set()
            es_amigo = any(ambito in amigos_de_la_clase for ambito in self.pila)
            
            if es_propio or es_amigo:
                return info
                
            # Si no cumple ninguna condición, bloqueamos por acceso denegado a miembro privado
            self.errores.semantico(linea, f"Acceso denegado: El miembro '{nombre_miembro}' de la clase '{propietario_real}' es privado.")
            return None
